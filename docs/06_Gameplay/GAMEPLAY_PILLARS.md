# Gameplay Pillars

Status: Approved

Version: 1.0

Owner: Game Design

---

# Purpose

This document defines the core philosophy behind Bastion Defense.

Every mechanic, feature, UI screen and future idea must reinforce these pillars.

If a feature does not strengthen at least one pillar, it should not be added.

---

# Pillar 1 — Protect, Don't Destroy

The objective is not to kill enemies.

The objective is to protect the Bastion.

Everything in the game should remind the player what they are defending.

The Bastion is the protagonist.

---

# Pillar 2 — Meaningful Decisions

Every decision should matter.

Examples:

- Tower placement
- Upgrade timing
- Economy management
- Hero positioning
- Resource spending

Avoid fake choices.

If one option is always optimal, redesign it.

---

# Pillar 3 — Easy to Learn, Difficult to Master

The first five minutes should be intuitive.

The next fifty hours should continue teaching the player.

Complexity should emerge naturally.

Never overwhelm new players.

---

# Pillar 4 — Readability Above Everything

The player should always understand:

- Why they lost.
- Why they won.
- What every tower does.
- What every enemy does.
- What to improve next time.

Confusion is bad design.

Difficulty is acceptable.

---

# Pillar 5 — Every Tower Has a Purpose

There are no "bad" towers.

Every tower should excel in a specific situation.

Every tower should also have weaknesses.

---

# Pillar 6 — The Battlefield Evolves

Maps should change.

Enemy compositions should change.

Player strategies should evolve.

No two waves should feel identical.

---

# Pillar 7 — Build Synergies

Victory comes from combinations.

Not from a single overpowered tower.

Examples:

Slow + Cannon

Poison + Archer

Barracks + Ballista

Support towers should be as valuable as damage towers.

---

# Pillar 8 — The World Feels Alive

The battlefield continues living while the player plays.

Wind.

Weather.

Villagers.

Wildlife.

Fire.

Everything reinforces immersion without distracting gameplay.

---

# Pillar 9 — Fair Challenge

Every failure should feel deserved.

Never rely on hidden mechanics.

Never punish the player with randomness alone.

Information should always be available.

---

# Pillar 10 — Long-Term Mastery

The game should reward:

Observation.

Planning.

Adaptation.

Experimentation.

Mastery should come from understanding systems.

Not memorizing numbers.

---

# Design Questions

Before adding any feature ask:

Does it improve decision making?

Does it improve readability?

Does it create interesting choices?

Does it support replayability?

Does it reinforce the Bastion?

If any answer is "No", redesign it.

# Success Criteria

A player should finish a session feeling:

"I could have defended the Bastion better."

Not:

"The game cheated."

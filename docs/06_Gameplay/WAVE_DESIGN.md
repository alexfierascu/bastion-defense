# Wave Design

Status: Approved

Version: 1.0

Owner: Game Design

---

# Purpose

This document defines how enemy waves are designed in Bastion Defense.

A wave is not simply a collection of enemies.

A wave is a tactical problem the player must solve.

Every wave should force the player to rethink their defense.

---

# Philosophy

Each wave asks a question.

The player answers through planning.

The next wave asks a different question.

Difficulty comes from changing the questions.

Not increasing numbers.

---

# Wave Formula

Every wave consists of:

Objective

↓

Primary Threat

↓

Supporting Threats

↓

Timing

↓

Economy Reward

↓

Preparation Time

---

# Wave Structure

Every wave should contain a purpose.

Examples

Teach.

Pressure.

Punish greed.

Reward preparation.

Force adaptation.

Introduce mechanics.

Never create filler waves.

---

# Wave Types

## Tutorial

Introduces one new mechanic.

Low pressure.

High clarity.

---

## Economy

Many weak enemies.

Rewards efficient builds.

Tests resource management.

---

## Pressure

Continuous enemy flow.

Minimal downtime.

Forces quick decisions.

---

## Elite

Small number of dangerous enemies.

Tests target priority.

---

## Siege

Focus on structures.

Introduces high-value targets.

---

## Mixed

Several enemy roles.

Requires balanced defenses.

---

## Boss

Unique mechanics.

Never simply "more enemies."

---

# Wave Progression

Early Game

Single enemy roles.

Clear lessons.

Medium Game

Two-role combinations.

Emerging synergies.

Late Game

Multiple simultaneous threats.

Mixed objectives.

End Game

Everything learned is tested.

---

# Enemy Composition

Every wave should contain:

Primary Threat

70%

Secondary Threat

20%

Support Threat

10%

Values are guidelines.

Not rules.

---

# Tempo

Good pacing follows:

Preparation

↓

Combat

↓

Recovery

↓

Preparation

Avoid continuous exhaustion.

---

# Escalation

Escalation should come from:

New behaviors.

New combinations.

Environmental changes.

Multiple attack routes.

Not raw health increases.

---

# Preparation Time

Players deserve time to think.

Preparation time should scale with complexity.

Never begin a difficult wave immediately after another.

---

# Multi-Lane Waves

Each lane should have a purpose.

Examples

Fast lane.

Heavy lane.

Flying lane.

Support lane.

Every lane should influence player decisions.

---

# Boss Waves

Bosses should change the battlefield.

Examples

Destroy walls.

Open new paths.

Summon reinforcements.

Force repositioning.

Bosses should never simply absorb damage.

---

# Rewards

Harder waves should reward:

More resources.

Better choices.

New opportunities.

Not automatic victories.

---

# Failure Analysis

After defeat the player should know:

Which wave failed.

Which enemy caused it.

Which defense collapsed.

What should change next run.

---

# AI Rules

When designing a wave ask:

What decision does this wave force?

Is there more than one solution?

Does it teach something?

Is it memorable?

Would experienced players enjoy solving it?

If any answer is "No",

redesign the wave.

Not by the number of enemies they contained.

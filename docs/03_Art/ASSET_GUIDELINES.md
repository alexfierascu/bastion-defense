# Asset Guidelines

Status: Approved

Version: 1.0

Owner: Art Direction

---

# Purpose

This document defines the quality standards for every visual asset created for Bastion Defense.

Whether the asset is generated by AI, modeled manually or purchased from a marketplace, it must satisfy these rules before entering the game.

---

# Philosophy

Every asset exists for a purpose.

Never create assets simply to fill empty space.

The player should believe every object was placed by someone who lives in this world.

---

# Asset Categories

Environment

Architecture

Nature

Props

Weapons

Armor

Characters

VFX

Audio

Every category follows the same quality principles.

---

# Purpose

Before creating any asset answer:

Why does it exist?

Who uses it?

How old is it?

How often is it used?

How is it maintained?

If these questions cannot be answered, redesign the asset.

---

# Readability

Assets must be readable from gameplay distance.

Large shapes define identity.

Medium shapes define function.

Small shapes reward close inspection.

Tiny details should never carry gameplay information.

---

# Silhouette

Every important asset should be recognizable as a black silhouette.

Examples

Arrow Tower

Barracks

Tree

Gate

Bridge

Enemy

If recognition depends on textures or colors, redesign it.

---

# Scale

Everything should respect human proportions.

Doors

Stairs

Windows

Bridges

Furniture

Weapons

Nothing should appear oversized unless gameplay explicitly requires it.

---

# Materials

Use only approved materials.

Granite

Limestone

Oak

Iron

Bronze

Leather

Canvas

Rope

Clay

Slate

Never introduce plastic, chrome or futuristic materials.

---

# Wear

Every asset ages.

Stone chips.

Wood cracks.

Iron rusts.

Bronze oxidizes.

Leather stretches.

Canvas fades.

Age should match usage.

---

# Damage

Damage tells stories.

Arrow impacts.

Fire damage.

Broken beams.

Replacement stones.

Emergency repairs.

Avoid random destruction.

---

# Modularity

Whenever possible assets should be modular.

Walls

Windows

Doors

Roof pieces

Columns

Stairs

Railings

Supports

Modules should combine naturally without visible seams.

---

# Reuse

Reuse is encouraged.

Duplicate appearance is not.

Variation should come from:

Rotation

Scale

Decals

Damage

Weathering

Vegetation

Lighting

---

# Optimization

Target low draw calls.

Reuse materials.

Share texture atlases.

Use instancing.

Create LODs.

Avoid unnecessarily high polygon counts.

---

# Collision

Collision should match visuals.

Players should understand immediately what blocks movement.

Never surprise the player with invisible collision.

---

# Gameplay

Gameplay always wins.

If visual accuracy hurts readability,

change the visuals.

Never sacrifice gameplay for realism.

---

# Asset Checklist

Before approval every asset must satisfy:

✓ Purpose

✓ Readability

✓ Correct Scale

✓ Correct Materials

✓ Natural Wear

✓ Proper Collision

✓ Modular if possible

✓ Optimized

✓ Matches Art Bible
